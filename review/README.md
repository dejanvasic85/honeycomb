# Question review files

Generated by `pnpm generate-questions`, gitignored (`review/*.json`) — these hold
unreviewed candidate questions, not something to commit.

## Workflow (docs/SPEC.md §5)

```bash
pnpm generate-questions --category food --age-band kids --count 15
```

This calls Claude for candidate questions, drops anything that normalises the same as an
existing bank entry, and writes the survivors to a timestamped file in this directory —
each row has `"approved": false`.

1. Open the file. For each question you want in the bank, flip `"approved"` to `true`.
   Delete rows you don't want, or just leave them `false` — either way they're skipped.
2. Run `pnpm apply-approved-questions review/<file>.json` (one or more files at once is
   fine). This writes a new `migrations/000N_generated_questions.sql` containing only the
   approved rows — nothing is applied to D1 yet.
3. Review the generated migration like any other diff, then apply it the normal way:
   `pnpm exec wrangler d1 migrations apply honeycomb --local` (add `--remote` once
   credentials exist).

No row reaches the database without a human explicitly setting `approved: true` first —
that's the gate from docs/SPEC.md §5, and it's why this script never calls
`wrangler d1 execute ... INSERT` itself.
